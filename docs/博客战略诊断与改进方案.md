**生成日期**: 2026-02-07
**基于**: 《micrabbit 技术博客调整版规划（引流导向+新增模块）》+ 博主深度访谈

## 二、原规划核心问题诊断

### 问题1：规划太重，恰恰是「执行力不够」的根源

原规划有135行，4大板块、6个工具模块、4个内容方向、12篇示例文章、5条运营技巧。**这不是规划，这是一本操作手册**。一个「三分钟热度」的人拿到这份规划，看第二页就会觉得「太多了，明天再说」——然后永远没有明天。

> **真相**：执行力差的人不是缺方法，是缺「最小启动单元」。你需要的不是更完善的规划，而是**砍掉80%，只留最小可执行单元**。

### 问题2：「引流」概念空转——流量源头是空的

原规划的引流闭环设计是：**博客内容 → 工具留存 → 跳转产品**。逻辑没问题，但忽略了一个前提——**流量从哪里来？**

- 博客刚建好，Google收录几乎为零
- 其他平台「刚注册还没开始」
- 没有任何存量流量

当前不是在做「引流优化」，而是在**从零到一获取第一批流量**。这完全是两件事。在没有流量的阶段，所有「工具内弹窗引导跳转」「侧边栏引流入口」都是自嗨——因为根本没人看到。

> **真相**：第一优先级不是「引流闭环设计」，而是**在外部平台创造可被搜索到的内容**，把人拉进来。博客是「基地」，但战场在外面。

### 问题3：定位太泛，无穿透力

原规划想覆盖「全栈开发者、AI技术爱好者、各领域技术从业者」——基本上等于「所有写代码的人」。在零粉丝阶段，越泛越没有穿透力。

博主有一个清晰的差异化优势但没有用好：**正在做RAG产品 + 懂全栈 + 懂AI工具链**。这三个组合在一起的人，在中文技术圈是稀缺的。

> **真相**：不要「全栈+AI」泛定位。应该是**「AI工具开发者」**——一个用全栈能力把AI落地成产品的人。全栈是能力，AI工具是标签。

**micrabbit · AI工具创造者** —— 「把AI从概念变成可用产品的全栈开发者」

不是教人写代码，不是教人用ChatGPT，而是**展示如何用全栈能力把AI变成真实可用的工具和产品**。

| 维度 | 为什么这个定位更好 |

| 求职加分 | 「我做过AI产品」比「我是全栈」值钱10倍 |
| IP属性 | 有故事可讲，有过程可展示 |

### 核心slogan

> **micrabbit · 把AI变成产品**

## 五、Phase 1 具体落地计划（第1-6周）

### 原则

不在博客上写给自己看的文章。每篇文章都必须能在外部平台获得流量。

### 砍掉什么

| 砍掉 | 原因 |
|------|------|
| ❌ 「skill收集与分享」模块 | 现阶段过早，Phase 2再考虑 |
| ❌ 「互动话题」「标签云优化」「搜索栏优化」 | 零流量阶段无意义 |
| ❌ 「每周固定更新时间」 | 先保证质量和持续性，不要给自己定deadline |
| ❌ 「每3天更新skill合集」 | 执行力跟不上，不切实际 |
| ❌ 「登录提交系统」 | 过度设计，静态展示就够 |

### 内容创作计划（4篇高价值文章，2周1篇）

1. **《我用AI一周做了一个RAG知识库产品（全栈技术选型+踩坑实录）》**
   - 讲自己的故事，有IP属性
   - 技术选型过程、架构设计、遇到的坑
   - 外部平台标题可调整为「一个全栈开发者做RAG产品的真实经历」

2. **《从0到1：给你的团队部署一个私有AI问答助手（手把手教程）》**
   - 实操教程，有搜索需求
   - 可关联RAG产品演示
   - 适合掘金/知乎获取长尾搜索流量

3. **《AI开发者工具链2026：我日常用的10个AI工具和工作流》**
   - 清单类内容，易收藏易转发
   - 自然植入自己的工具和产品
   - 适合知乎获取流量

4. **《提示词工程实战：我在RAG产品中如何优化Prompt质量》**
   - 为Phase 2的Prompt优化工具铺路
   - 有实操有深度，不是泛泛而谈
   - 贴合AI趋势，搜索需求大

**为什么是这4篇？**
- 每篇都和正在做的RAG产品有关（不用额外造素材，减少执行阻力）
- 每篇都有「个人经历+实操教程」（有IP属性，不是纯教程搬运）
- 每篇都适合在掘金/知乎获得流量（有搜索需求+话题热度）

### 外部平台操作

- 每篇博客同步到掘金、知乎（标题可微调适配平台调性）
- 文末加一行：「更多AI工具开发实战 → micrabbit.github.io」
- 在GitHub上开一个 awesome-ai-tools-dev 的repo，收集你的文章和工具

### 每周最小执行单元（防止三分钟热度）

| 时间 | 任务 | 产出 | 耗时 |
|------|------|------|------|
| 周一-周三 | 写1篇文章初稿 | 博客markdown文件 | 3-4h |
| 周四 | 润色+配图+发布到博客 | 博客上线 | 1-2h |
| 周五 | 同步到掘金+知乎+标题优化 | 外部平台内容 | 1h |
| 周末 | 可选：改进博客/做工具 | 渐进式改进 | 2-3h |

> **关键设计：每周只需要5-7小时就能完成。剩下的时间做RAG产品。不要贪多。**

## 六、Phase 2 具体落地计划（第7-12周）

### 原则

只做1-2个真正有传播力的工具，不要搞工具矩阵。

### 工具方向（二选一，先做一个）

#### 方案A：Prompt优化工具（推荐优先做这个）

| 维度 | 设计 |
|------|------|
| 形态 | 前端规则引擎 + 可选LLM API增强 |
| 核心功能 | 输入prompt → 分析结构/评分 → 优化建议 → 一键生成优化版本 |
| 差异化 | 不做通用prompt模板库（太多了），做**prompt质量诊断工具**——「你的prompt好不好？哪里可以改？」 |
| 引流点 | 工具免费用，底部一行字「由micrabbit开发，基于RAG产品同款prompt优化引擎」 |
| 技术实现 | 基础：前端规则引擎（结构完整性、要素检查、评分）；进阶：调用LLM API做深度优化 |

#### 方案B：AI Skill/Workflow收藏夹

| 维度 | 设计 |
|------|------|
| 形态 | 在线的AI工作流配置收藏+分享平台 |
| 核心功能 | 浏览/搜索/复制各种MCP Skills、Cursor Rules、GPT Instructions |
| 差异化 | 不做分散的prompt模板，做**结构化的AI配置文件收藏**——开发者真正能直接用的东西 |
| 引流点 | 内容本身自带传播性（收藏/转发），底部关联RAG产品 |

### 工具发布后的传播路径

1. GitHub开源 → README写清楚用途+截图 → 提交到各种awesome列表
2. 掘金/知乎发《我做了一个XXX工具，免费开源》类型文章
3. ProductHunt / V2EX / 即刻等平台发布

## 十、对抗「三分钟热度」的执行策略

1. **不要再优化这个规划了**。规划已经够好了。问题不是规划不够完善，是做得不够多。从今天起，关闭规划模式，打开执行模式。

2. **第一篇文章就写RAG产品**。最不缺素材的就是正在做的事情。「我为什么要做这个产品 → 技术选型过程 → 遇到的坑 → 当前效果」——这篇文章今天就能开始写，不需要任何准备。

3. **给自己定一个「最低限度」而不是「理想目标」**。不是「每周一篇高质量文章」，而是「这两周无论如何要发一篇，哪怕只有800字」。完成 > 完美。

4. **博客网站的风格调整可以慢慢做，但第一篇文章今天就发**。当前博客样式已经不差了，不要用「网站还没改好」当不发文章的借口。

5. **用「2分钟规则」启动**。每次觉得「不想写」的时候，告诉自己「只写2分钟」。打开编辑器，写一句话。大多数时候，2分钟后你会继续写下去。

6. **公开承诺**。在掘金/知乎发一篇「我要在接下来3个月做XX」的帖子。公开承诺的心理压力会帮助你坚持。

## 十一、网站风格调整建议

### 当前风格分析

当前博客是 **Swiss/Neo-Brutalism风格**：
- 主色：#ff4d00（国际橙）
- 字体：Plus Jakarta Sans（标题）、系统字体栈（正文）、JetBrains Mono（代码）
- 布局：max-width 1000px 居中，bento grid dashboard
- 视觉元素：浮动光球、glassmorphism、大胆几何设计
- 暗色模式：已实现，通过CSS变量体系

### 风格方向建议

**不建议走「温暖个人风」，建议走「专业但有温度的现代科技风」**

| 纯温暖风 | 专业+温度科技风 |
|----------|----------------|
| 暖色调+圆角+手绘 | 沉稳色彩+现代排版+个人化元素 |
| 适合生活类/设计类博主 | 适合AI工具开发者 |
| 不够专业 | 专业感+人格化并存 |
| 与技术受众期待不匹配 | 技术开发者觉得可信赖 |

**个人IP不一定要靠视觉温暖来建立，通过内容的个人化（讲自己的故事、踩坑、经验）来建立IP更真实。**

**目标参考：Linear.app / Raycast.com 的专业感 + 加入个人化元素（头像、签名、故事感文案）**

## 十二、网站风格改造提示词

```
你是一个资深的前端UI/UX设计师和开发者。我需要你帮我改造一个个人技术博客的视觉风格。

## 当前状态

## 博客定位
- 博主身份：AI工具创造者 —— 用全栈能力把AI落地成产品的开发者
- 受众：技术开发者、AI工具爱好者
- 博客内容：AI产品实战、AI工具与工作流、在线工具
- 有一个RAG知识库产品需要引流
- slogan：「micrabbit · 把AI变成产品」

## 目标风格
「专业但有温度的现代科技风」，具体参考方向：

### 色彩系统
- 主色调：从激进的橙色(#ff4d00)调整为更沉稳但有辨识度的色彩，建议方向：
  - 方案1：深蓝紫渐变系（类似Linear），传达专业+创新
  - 方案2：靛蓝+琥珀双色系（类似Raycast），冷暖平衡，专业但不冷
  - 方案3：保留暖色但降低饱和度，如柔和的珊瑚橙/暖棕，配深色背景
- 背景：浅色模式用微暖的灰白（不要纯白），暗色模式用深灰蓝（不要纯黑）
- 需要保持足够的对比度和可读性

### 字体
- 标题字体：保留Plus Jakarta Sans或换为Inter/Geist，要有力量感但不要太aggressive
- 正文字体：系统字体栈，确保中文阅读舒适
- 代码字体：保留JetBrains Mono

### 布局与组件
- 保持当前的max-width: 1000px居中布局（好的设计，不要改）
- 首页Hero区：弱化「Available for work」标签，强化个人IP元素：
  - 加入一句有态度的tagline（如「用代码把AI从论文变成产品」）
  - 加入微头像或个人logo
  - CTA按钮改为「看我的作品」和「试试我的AI工具」
- 卡片设计：保留bento grid布局，但调整视觉层次：
  - 减少纯装饰性元素（去掉浮动光球）
  - 增加内容密度（让人一眼看到有价值的东西）
  - 卡片hover效果柔和一些（当前scale变换太大）
- 工具页面：保持功能导向，但增加一行引导文案空间（用于未来加引流链接）

### 个人IP元素
- 在Header或Footer加入个人签名/标语的位置
- 博文页面加入「作者卡片」区域（头像+一句话介绍+社交链接）
- 侧边或底部预留「产品推荐位」（不急着加内容，先留位置）

### 动效
- 保持页面切换过渡动画
- 减少装饰性动效（浮动光球、过度的parallax）
- 增加微交互：按钮hover、卡片进入视口淡入

### 请注意
- 不要彻底推翻现有设计，而是「进化」——保留好的骨架，调整视觉气质
- 所有颜色修改通过CSS变量（--pk-color-*）实现，确保暗色模式同步更新
- 不要使用渐变背景大面积铺满，保持克制
- 中文排版要舒适，行高1.8-2.0，段落间距充足
- 保持Element Plus组件的风格一致性
```
