# 我用 AI 一周做了一个 RAG 知识库产品：从 0 到 1 的实战沉淀

> **前言**：在 AI 时代，复刻一个功能并不难，难的是如何在极短的时间内，从零构建出一个真正可用、具备商业潜力的 RAG（检索增强生成）产品。上周，我利用业余时间，基于“闲管家”项目的实战经验，在一周内上线了一个垂直领域的 RAG 知识库产品。本文将深度复盘整个技术选型、核心实现及踩坑经验。

## 一、 为什么是 RAG？

大语言模型（LLM）虽然强大，但存在“幻觉”和“时效性”两大硬伤。对于企业或个人开发者来说，私有数据的安全性和准确性是第一位的。

RAG（Retrieval-Augmented Generation）通过“检索 + 生成”的方式，让模型先在给定的知识库中寻找答案，再结合 LLM 的表达能力输出。这种方式不仅降低了推理成本（不需要微调模型），还极大地提升了回答的可靠性。

## 四、 核心技术干货：RAG 的“生死三关”

做一个 RAG Demo 很简单，但要做到“好用”，必须打通以下三个核心环节。

### 1. 文档清洗与切片（Chunks）的艺术

这是最容易被忽视，却最影响效果的一环。
- **踩坑点**：直接按字符数硬切，导致上下文断裂。
- **解决方案**：采用 `RecursiveCharacterTextSplitter`，并设置合理的 `chunk_overlap`（重叠度，通常设为 10%-15%）。
- **实战经验**：对于技术文档，建议按 Markdown 的标题层级进行逻辑切片。

### 2. 向量检索的“双塔策略”

单纯的语义向量检索在处理“特定名词”时表现糟糕。
- **优化方案**：**混合检索（Hybrid Search）**。
  - **向量检索（Dense）**：负责理解意图和语义相似度。
  - **关键词检索（Sparse/BM25）**：负责精准匹配产品型号、人名、缩写。
- **进阶技巧**：加入 Rerank（重排序）模型。先粗筛出 50 条，再用 Rerank 模型精选出 Top 5，准确率能提升 30% 以上。

### 3. Prompt 的结构化设计

不要只给模型一段文字，要给它一个“人设”。
- **系统提示词模版**：
  ```markdown
  # Role
  你是一个专业的知识库助手。
  # Context
  以下是从本地知识库检索到的参考内容：{context}
  # Constraints
  1. 仅基于参考内容回答。
  2. 如果参考内容中没有相关信息，请诚实告知。
  3. 保持专业、简洁的语气。
  ```

## 五、 实战沉淀：那些 AI 没告诉你的坑

在开发“闲管家”和这款 RAG 产品的过程中，我总结了几个核心心得：

1.  **数据的质量决定上限**：RAG 的核心不是 AI，而是数据。1G 的垃圾文档不如 100KB 的精排 QA。
2.  **不要迷信全自动**：在处理核心业务逻辑时，人工微调的 Prompt 远比模型自动生成的要稳定。
3.  **流式响应（Streaming）是刚需**：对于 RAG 这种推理时间较长的应用，流式输出能极大缓解用户的等待焦虑。
